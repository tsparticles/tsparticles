# tsParticles 4.5.0 — Fluid Interaction, MCP `generate_code`, Emitter Draw/Drag & Workspace Test Coverage Release Plan

## Status

4.5.0 scope is now defined as:

1. **Fluid particle behavior via collisions mode** — the DDR-based liquid simulation moved from the scrapped 4.4.0 v3 attempt to the v5 "fluid-as-collision-mode" design.
2. **MCP server `generate_code` tool** — a deterministic code generator tool for `@tsparticles/mcp-server`.
3. **Emitter draw & drag** — emitters can be rendered on the canvas and dragged with the mouse, mirroring the absorber plugin capabilities.
4. **Workspace test coverage expansion** — broader unit-test coverage beyond the Feature D engine tests: engine option `load()` classes, engine utils/updater math, the `@tsparticles/configs` preset catalog, deterministic noise libs, geometry spot checks, and fixing false-green test targets.
5. **Absorber splitting (contingency)** — `absorbers.split` + `absorber-split` click mode, requested in issue `#5320` and prototyped in PR `#5923` (external contributor, currently unresponsive to review). Full plan in `ABSORBERS_SPLIT_PLAN.md`. If the PR is abandoned (see decision gate there), the feature is implemented in-house, incorporating all review findings; if it merges, this feature is dropped from 4.5.0 scope.
6. **Website updates (final gate)** — update of the official websites to the released 4.5.0 packages:
   `websites/website` (main, always) plus `websites/confetti` / `websites/ribbons` only if needed.
   **This is always the last task executed, no matter which other plans (4.5.0 scope changes or later
   releases) are in flight**, and it stays **pending** until the update is explicitly approved — the
   4.5.0 release is not complete until it runs.
7. **Code-based error messages** — engine and browser-package errors get stable `TSP-xxxx` codes;
   non-minified builds keep the full message, minified builds ship only the code plus a link to a
   website errors page (`https://particles.js.org/docs/errors/#TSP-xxxx`). Implemented via the
   existing bundler constant-folding (`process.env.NODE_ENV`), no new build tooling. Full plan in `ERROR_MESSAGE_CODE_PLAN.md`.

HDR color fixes and code review fixes shipped in 4.4.0. See `4.4.0_PLAN.md`.

Primary technical sources: `FLUID_INTERACTION_PLAN.md`, `MCP_GENERATE_CODE_PLAN.md`, `EMITTERS_DRAW_DRAG_PLAN.md`, `WORKSPACE_TEST_COVERAGE_PLAN.md`, `ABSORBERS_SPLIT_PLAN.md`, `ERROR_MESSAGE_CODE_PLAN.md`.

## High-Level Goal

Ship a stable `particles.collisions.mode = "fluid"` behavior that:

- uses DDR-based neighborhood resolution (correct `q` factor + velocity reconstruction)
- remains mutually exclusive with `bounce` / `absorb` / `destroy`
- requires no new plugin package or loader
- preserves backward compatibility for existing collision modes

and add a deterministic `generate_code` MCP tool that:

- turns a natural language description into complete, ready-to-use code
- favors specialized bundles (`@tsparticles/confetti`, `@tsparticles/fireworks`, etc.)
- stays a pure function (no filesystem I/O, no network, no LLM dependency)

and extend the emitter plugin so that:

- emitters can be drawn on the canvas (shape rendering, toggle via `draw`)
- emitters can be dragged with the mouse while continuing to emit (toggle via `draggable`)

and broaden workspace test coverage so that:

- every engine option `load()` class is pinned by tests (61 classes, previously ~5 `it()`)
- deterministic math (engine utils, updaters, noise libs, easings) is exact-value tested
- the configs/presets/bundles catalogs (256 loadables) are guarded against option-shape regressions
- feature packages (shapes/updaters/interactions/effects/paths/exports) get deterministic geometry/math coverage
- every advertised test target actually runs ≥1 real test — CLI (25 projects) and wrappers (23) included, demos excluded

## Feature F — Absorber Splitting (contingency for PR #5923)

> **Status: contingency — not yet in scope.** Requested in issue `#5320` ("Absorber Split on Click or
> Size limit reached") and prototyped in PR `#5923` by an external contributor who has stopped
> responding to review. This feature is added to 4.5.0 **only if** the PR is abandoned per the
> decision gate in `ABSORBERS_SPLIT_PLAN.md` (last PR activity 2026-09-13; trigger ≈ 2 weeks with no
> response). The in-house implementation must incorporate every review finding (R1–R8: restore the
> `particle.destroyed` break, `absorber-split` mode name, hoisted `clickPosition`, validated/clamped
> `split.quantity`, replacement-created-before-removal ordering, growth guard against per-frame split
> loops, rejection handling, unit-test coverage).

### Scope

1. `absorbers.split` options block (`enable: boolean`, `quantity: number`)
2. Auto-split when the absorber reaches a configured `size.limit.radius` / `size.limit.mass`
3. `absorber-split` click interactivity mode for manual split of the absorber under the cursor
4. On split: replacement absorber (original options) + `quantity` particles spawned at the old position
5. Unit tests under `utils/tests/src/tests/` following Feature E conventions

### Phases

1. **Options contract** — `IAbsorberSplit` + `AbsorberSplit`, wired into `IAbsorber`/`Absorber` (load via `loadProperty`)
2. **Split detection** — `AbsorberInstance.shouldSplit()` with the growth guard (never at creation)
3. **Split execution** — `AbsorbersInstancesManager.splitAbsorber()` (replacement first, then remove + push particles), rejection-safe
4. **Auto hook** — `AbsorbersPluginInstance.update(delta)` per-frame split check; `particleUpdate` keeps the `particle.destroyed` break
5. **Click mode** — `AbsorbersInteractor` `absorber-split` branch (nearest-absorber hit-test, `.some` add-guard restored)
6. **Tests + docs** — option/guard/ordering/click coverage; `markdown/Options/Plugins/Absorbers.md` + interactivity mode docs

## Risks and Mitigation

### Risk 1 (Fluid): classic mode regression

Mitigation:

- strict mode branching
- targeted regression tests for `bounce`, `absorb`, `destroy`

### Risk 2 (Fluid): fluid instability (jitter/explosion)

Mitigation:

- enforce formula correctness (`dir * q * (P + Pnear * q) * 0.5`)
- force clamp, distance epsilon guards
- velocity reconstruction from `prevPos`
- conservative defaults

### Risk 3 (Fluid): boundary artifacts

Mitigation:

- soft spring + hard clamp sequence in fluid branch
- documented recommendation for `move.outModes`

### Risk 4 (Fluid): performance drop on dense scenes

Mitigation:

- neighbor cap
- grid-based queries
- avoid hot-loop allocations

### Risk 5 (MCP): free-form descriptions produce unusable output

Mitigation:

- deterministic keyword matching with priority-ordered bundles
- framework-specific templates with overrides
- comprehensive bundle/options/codegen tests

### Risk 6 (Emitters): drawing changes visual behavior for existing users

Mitigation:

- gate behind explicit `draw` option (default `true` for parity with absorbers; can ship
  default `false` to preserve current invisible-emitter behavior if the team prefers)
- `context.save()/restore()` to avoid state leakage into particle rendering

### Risk 7 (Emitters): drag fights DOM-linked emitters or `resize()`

Mitigation:

- exclude `domId`-linked emitters
- `setPosition()` updates position + shape without recomputing size from options
- rectangular half-width/half-height hit-test (emitters are not circular like absorbers)

### Risk 8 (Coverage): option-tree tests break on value/identity assertions during refactors

Mitigation:

- assert default/merge **values and semantics**, not internal object identity
- a failing `load()` test is a regression signal to review, not a test to silently rewrite

### Risk 9 (Coverage): configs sweep (226 loads) slows the suite

Mitigation:

- single vitest file with modest `maxWorkers`; if > 30s, split into fast structural check + smaller
  live-load subset; drop the package-local duplicate if the `@tsparticles/tests` sweep suffices

### Risk 10 (Coverage): package-local vitest configs collide with the workspace runner

Mitigation:

- package-local configs stay minimal (`include` own `src/*.test.ts` only), no coverage/maxWorkers
  overrides, verified standalone + from repo root

### Risk 11 (Coverage): Angular wrapper `ng test` cannot run headless in CI

Mitigation:

- if karma/chrome is unviable, swap the wrapper to vitest + jsdom smoke and document the rationale;
  outcome is a real, runnable test — never a false-green target

## Rollback Strategy

### Fluid

1. Keep enum/options behind internal state or revert fluid additions
2. Ship 4.5.0 without fluid mode if stability/performance criteria are unmet
3. Preserve the fluid-as-collisions-mode architectural decision for next iteration

### MCP `generate_code`

1. Keep the tool behind the existing `src/tools/` structure; it is additive-only
2. If codegen quality is inadequate, do not expose it in MCP `ListTools` and fix in follow-up

### Emitter draw & drag

1. Additive-only options (`draw`, `draggable`); removing them restores 4.4.0 behavior
2. If drawing causes visual regressions, ship with `draw` defaulting to `false` in 4.5.0
3. Dragging is isolated in `EmittersInteractor` and gated by mode enable states — trivially removable

### Absorber splitting (Feature F contingency)

1. Additive-only (`split.enable` defaults `false`); removing the options, the `absorber-split` branch and the
   `update()` hook restores 4.4.0 frame behavior exactly
2. If the PR #5923 author re-engages, prefer merging upstream (after R1–R8) over the in-house port and drop
   the contingency work to avoid conflicts

### Engine particle tests (Feature D)

1. Mostly test-only; rollback is reverting `Particles.ts` extension and removing
   `ParticleGroups.ts` / `ParticlesEvents.ts`.
2. If a limit-invariant test exposed and fixed an engine bug, the fix is isolated in
   `ParticlesManager`/`Container` and independently revertible; it ships with its own changelog entry.
3. No runtime impact on 4.4.0 behavior when rolled back.

### Workspace test coverage expansion (Feature E)

1. Nearly all additive test-only work; rollback is deleting the new test files and their
   package-local config/scripts (`OptionsLoad.ts`, `EngineUtils.ts`, `ContainerLifecycle.ts`,
   `UpdaterMath.ts`, `Configs.ts`, `Presets.ts`, `Bundles.ts`, `ShapeGeometry.ts`, `Updaters.ts`,
   `InteractionGeometry.ts`, `Effects.ts`, `PathGenerators.ts`, `Exports.ts`, `PluginOptions.ts`,
   noise/easing/configs/cli/wrapper tests + any package-local vitest configs/scripts).
2. If a test exposed and fixed an engine/package bug, the fix is isolated in the affected source
   and independently revertible with its own changelog entry.
3. Additive `test` scripts + vitest configs in noise/configs/cli/wrapper packages do not affect the
   published runtime; rollback removes them without impact.
4. No runtime impact on 4.4.0 behavior when rolled back.

### Error messages as codes (Feature G)

1. Converted throw sites revert to their original strings; `ErrorCodes.ts`/`ErrorMessages.ts`/
   `ErrorUtils.ts` + tests + website page deleted → identical 4.4.0 behavior.
2. The rollup `replace` token is inert if no code uses `process.env.NODE_ENV`; removing it restores
   the exact prior rollup output.
3. Partial rollback: keep the engine conversion (biggest size win) and drop the feature-package
   sweep; codes remain stable and reused only forward.
