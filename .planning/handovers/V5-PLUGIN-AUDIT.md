## E8 closure — 2026-11-24

Source reviewed: `plugins/emitters/src/ShapeManager.ts`,
`addEmittersShapesManager.ts`, `getEmittersInstancesManager.ts`, `interaction.ts`,
`plugin.ts`, and engine `PluginManager.ts` registration paths. `ShapeManager`
owns its generator Map per instance; the engine-scoped plugin manager owns the
shape manager and the emitter-instance-manager cache is a `WeakMap` keyed by
that plugin manager. Same-name generator registration preserves the first
registration within one owner and remains isolated across owners. Plugin
registrations are de-duplicated by plugin id within each engine.

`utils/tests/src/tests/EngineInstances.ts` now also registers custom preset,
easing, shape, and path extensions on separate engines; initializes in reverse
order and concurrently; and repeats the same loader on one engine to verify
idempotence. Engine/container disposal behavior is covered by E4 lifecycle and
load-order regressions. This G1 result is paired with the package matrix and
compatibility evidence below.

The development error-message catalog in `engine/src/Utils/ErrorUtils.ts` is a
module-level mutable map extended by plugin catalogs. Its values are message
templates indexed by stable error codes, not engine-owned simulation state. Other
classified shared state includes immutable easing/color definitions, deterministic
polygon geometry caches, and the sounds user-activation latch. Per-owner mutable
registries and caches remain on their Engine, PluginManager, Container, or drawing
context. The background-canvas callback previously shared its hue counter across
contexts; it now stores counters in a `WeakMap` keyed by drawing context.
