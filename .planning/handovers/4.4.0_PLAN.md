# tsParticles 4.4.0 — HDR Color Fix & Rendering Modes Release Plan

## Status

4.4.0 scope is now defined as:

1. **HDR color fidelity fixes** — tone mapping, linear-space color mixing, configurable `peakNits`, display-aware re-evaluation, plus new HDR rendering modes (`natural` / `vivid` / `cinematic` / `dynamic`).
2. **Code review fixes** — the 6 confirmed wrapper bugs and 4 optional fixes from the wrapper framework audit.

The fluid-in-collisions work previously planned for 4.4.0 has been moved to 4.5.0. See `4.5.0_PLAN.md`.

Primary technical sources: `HDR_COLOR_FIX_PLAN.md`, `FIX-PROMPT.md`.

**Status: ✅ Implemented.** HDR fix + rendering modes fully implemented in the engine and threaded through all consumer packages; FIX-PROMPT fixes applied (including the remaining `ribbons.lazy.ts` fallback). Full test suite green (168/168).

Ship a stable 4.4.0 release that:

- fixes HDR color clipping/distortion via tone mapping and linear-space mixing
- exposes user-selectable HDR rendering mode presets
- lands the audited wrapper fixes (Lit, Solid, Vue2, WebComponents, Angular-fireworks, Ribbons + 4 optional)

## Scope Definition

## In scope

1. ACES Filmic tone mapping in `ColorUtils.getHdrStyleFromRgb()`

7. Merge and verify the 6 confirmed wrapper fixes + 4 optional fixes

1. Fluid particle behavior via collisions mode — moved to 4.5.0
2. New `@tsparticles/interaction-particles-fluid` package
3. MCP `generate_code` tool — moved to 4.5.0

## Feature F — Code Review Fixes

All fixes are already implemented (marked `✅ DONE` in `FIX-PROMPT.md`). The plan step is verification and release inclusion.

### Bug fixes (confirmed)

1. **Lit** — `loadTheme(changedProperties.get("theme"))` loads the previous value; use `this.theme`
2. **Solid** — missing `loadId` guard causes stale promise to overwrite `container`
3. **Vue2** — old container not destroyed on `id` change
4. **WebComponents** — `data-id` attribute updates ignored because `super.id` not synced
5. **Angular-fireworks** — missing `#loadId` guard races `#fireworksInstance`
6. **Ribbons** — bare `fire()` call replaces create-time options with `{}`

### Optional fixes (implemented)

- **A.** OffscreenCanvas guard in worker context (`RenderManager.ts`)
- **B.** Qwik — reject on missing `initParticlesEngine`
- **C.** Svelte — track options without `JSON.stringify`
- **D.** Stencil — forward both `url` and `options`

### Verification

1. `pnpm exec vitest` — all tests must pass (152/152 baseline)
2. `pnpm nx run-many -t lint` — no new errors in changed files
3. Toggle theme in each wrapper demo and confirm correct theme loads

Exit criteria:

- all tests pass
- lint clean on changed files

## Risks and Mitigation

### Risk 1: tone mapping changes perceived colors for existing HDR users

Mitigation:

- `hdrMode: "natural"` default targets perceptual equivalence with SDR
- SDR (`hdr: false`) path untouched
- release notes document the change

### Risk 2: linear mixing breaks existing color call sites

Mitigation:

- `colorMix()` `hdr` param default preserves legacy gamma-space behavior
- update all call sites in one pass with per-consumer compile verification

### Risk 3: new options break type surface

Mitigation:

- additive-only `hdrMode` / `peakNits` with safe defaults
- export from `exports.ts` and verify public option shapes

### Risk 4: wrapper fixes regress

Mitigation:

- all fixes already implemented and verified in the audit
- rerun full vitest suite + lint before release

## Rollback Strategy

If HDR changes do not meet fidelity/performance acceptance criteria in time:

1. Gate `hdrMode` / `peakNits` behind their defaults (behave as current HDR)
2. Ship 4.4.0 with only the FIX-PROMPT fixes (low risk, already verified)
3. Keep the HDR fix spec `HDR_COLOR_FIX_PLAN.md` for 4.4.1/next iteration
